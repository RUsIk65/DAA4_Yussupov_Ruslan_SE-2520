# Student verification

Run from the repository root with Python 3.12+ and JDK 21 on PATH:

```sh
python tools/run.py --check
python tests/student/test_solution.py
python tests/student/benchmark.py
python tests/student/environment.py
```

`test_solution.py` compiles Java, checks 12 named fixtures, runs 4,064 deterministic small oracle cases twice in a persistent mixed-request process, then runs 20 domain-limit cases. Seed: 20261107. Total: 8,160 responses. Any wrong value, invalid witness, malformed response or 20-second batch timeout makes the command fail. Java uses one active processor and a 384 MiB heap. The output schema/witness checker is supplied by the course; expected values come from independent test oracles and closed-form large-case expectations.

- `fixtures.json`: readable input and expected output examples.
- `fixture-results.json`: actual answers and semantic pass flags for those examples, generated by the tests.
- `test-results.txt`: captured local student run.
- `public-results.txt`: captured supplied public run (44 cases and a repeated mixed batch).
- `setup-results.txt`: supplied startup check.
- `SearchBenchmark.java`, `benchmark.py`: in-process benchmark with correctness checks, 200 warm-ups and three measured batches of 50 calls per case/method.
- `benchmark-results.md`: all raw per-batch times normalized to microseconds per invocation and medians.
- `environment.py`, `environment.txt`: recorded runtime and hardware.

The test oracle may use built-in search/suffix strings because it is independent verification code; the submitted implementation does not. Tests are not imported by `Main` and do not affect the JSON Lines interface.

To refresh logs in PowerShell:

```powershell
python tools/run.py --setup 2>&1 | Tee-Object tests/student/setup-results.txt
python tools/run.py --check 2>&1 | Tee-Object tests/student/public-results.txt
python tests/student/test_solution.py 2>&1 | Tee-Object tests/student/test-results.txt
```

Check the command exit code as well as the log. `benchmark.py` writes its result file directly. If measurements are regenerated, update the corresponding table and discussion in `ANALYSIS.md` to match the new run.
